## 1. 执行原则与范围变更

1. 保留已经可用的语音输入。用户已反馈应用内语音可以正常聆听、感知，仍在手工测试；这不等于后台免跳转、所有旧系统或所有云服务已经验收。
2. 新要求优先：账户、风格市场、词典和加密云同步现在属于 iOS 产品范围。旧的“个人预览暂不做账户／同步”不再作为排除理由，但也不能把尚未实现的功能写成已经完成。
3. 普通模式仍默认打包 SenseVoice 本地 ASR，不预配 LLM／云端密钥。后处理、翻译、帮写需用户实际配置并启用相应能力。
4. 尽量复用 OpenLess 桌面现有 Core、领域模型、词典、历史、风格包和同步协议；不在 Swift 重写一套网络、提示词或加密算法。
5. App／键盘保持原生。键盘使用 MIT 源码版 KeyboardKit 9.9.0 与 Rime，不运行 Rust Core／ASR 模型，不打开麦克风、不保存 API 密钥。
6. 不重置、提交、推送或覆盖工作区中原有桌面、Android、ASR 改动。用户历史、词典、配置和凭据不得为了测试被清空。
7. 只保留一个 iOS 模拟器。不删除物理设备、当前保留设备的数据或仍需复用的模型资源。
8. iOS 的选区润色入口按最新要求删除；历史重新润色、语音后处理和帮写是不同功能，仍然保留。
9. Typeless 用来比较交互与信息结构，不复制其品牌、私有词库、商业实现、后端凭据或订阅权益。
10. 最新执行方式：先补齐本文及执行清单，再按独立组件交给其他 Agent；全部使用 GPT-6.1、high，不得使用 xhigh／max 或其他模型。完成实现后由 Codex 独立 review，主 Agent 处理发现并做最终检查。
11. 最终验收必须使用 Orca 自带模拟器实际操作与截图，不以 CLI 返回 ok、源码检查、单元测试或构建成功替代界面验收。只操作保留设备，操作前确认没有录音。
12. 用户随后追问“之前能弹、为什么现在不能”：根因仍未查明，不能再断言一定是虚拟机问题。将系统输入框与 OpenLess 输入框对照、旧版本与当前版本回归列入执行清单；不清空数据、不用反复强制聚焦掩盖故障。

### B. 历史

| ID | 功能／要求 | 完成标准 |
| --- | --- | --- |
| HIST-01 | 字体与排版 | 对齐 OpenLess 原有界面；正文／原文／时间／状态层级清楚，长段落可读、可选中，支持大字号和深浅色 |
| HIST-02 | 历史管理菜单 | 在历史页面提供刷新、清空等操作；清空需确认，执行真实 Core 动作，不能清空别人的云端／其他账户数据 |
| HIST-03 | 单条详情 | 可查看原文、最终处理结果、时间／时长／错误状态；不存在的字段不伪造 |
| HIST-04 | 复制与删除 | 支持复制原文、复制最终文本、删除单条；区别二者，不把润色结果当原文 |
| HIST-05 | 重新润色 | 对已有记录主动选择当前可用模式／风格／LLM 重跑；保留原文，显示处理中／错误／新结果，不假装成功 |
| HIST-06 | 播放录音 | 只对真正存在且可读取的音频资产显示播放器；播放状态、时长、停止与错误真实可用 |
| HIST-07 | 未完成 ASR 的录音导出 | 只有录音存在、ASR 尚未完成／失败等符合状态的记录才显示导出；使用真实文件与系统分享／文件导出 |
| HIST-08 | 已转写内容不导出录音 | 已转换完成的记录不显示“导出录音”，不能仅因有历史条目就展示导出按钮 |
| HIST-09 | 流式／无音频的降级 | 若没有可恢复的原始录音，不造播放器或导出；仍支持重新润色、删除、看原文和复制原文 |
| HIST-10 | 音频生命周期 | 明确音频在哪些状态保留、如何关联记录、何时删除；音频存主 App 私有目录，不进入键盘共享容器、不默认加入云同步 |

说明：用户规定了“完成转写后无录音导出”，并未明确要求“完成后一定立即删除一切音频”。播放能力和保存策略要结合现有 Core 音频资产契约设计，不擅自把两者混为一个开关。

### C. 键盘语音、翻译、帮写与润色模式

| ID | 功能／要求 | 完成标准 |

| KBD-08 | 无障碍与操作反馈 | 提示不只靠颜色；按下、录音、取消、翻译目标、帮写状态可读；减少动态效果、横屏和大字号不丢功能 |
