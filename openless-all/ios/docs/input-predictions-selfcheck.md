# 输入联想自查（2026-10-20）

结论：本地词库完整，候选链路能连续工作，但相关性仍有明显弱项，不能记为用户体验验收通过。没有大改词库或排序；只修复了中文 `limit <= 0` 仍返回一个候选的明确边界错误。

## 方法与资源

用 `xcrun swiftc Keyboard/KeyboardPredictionEngine.swift <临时 main.swift>` 直接编译当前 Swift 引擎，连接 `Resources/Prediction/lexicon.sqlite3`，运行 29 组中英文/边界样例；没有用 Python 复刻排序代替真实引擎。另用 SQLite 只读连接执行完整性与条目数检查。

- 数据库 `PRAGMA integrity_check = ok`；SHA-256 `bbec6f0934bfd18e25c981fe81246c7d2eb8195151e64b65ddda115afe692e03`，与 manifest 一致。
- 英文单词 82,833；英文 bigram 115,314；中文续词 178,855，与 manifest 一致。
- 9 个原生断言通过：零/负上限为空、limit=1、最长中文前缀、标点断句、英文 thank→you 与 want→to、句末清空、全大写保持。
- 没有运行完整 App/UI 测试套件；UITextChecker 的系统纠错/补全、Rime 组合串排序和真实候选栏触控不在本次命令行样例的覆盖范围。

## 实际候选（按引擎顺序）

| 输入上下文 | 候选摘录 | 判断 |
| --- | --- | --- |
| `th` | `th, That, This, They, Their, There` | 原输入保留首位，常用补全排序合理。 |
| `thank ` | `you, the, all, my, them` | 第一候选有直接相关性。 |
| `I ` → `I want ` → `I want to ` | `have/am/was` → `to/it/a` → `the/be/a/get/do` | 连续输入有候选，只有前一单词参与 bigram，长句语义没有保留。 |
| `good m` | `m, more, my, may, me, most, music, make` | 常见搭配 morning 未进入前八，下一词语境约束较弱。 |
| `HEL` | `HEL, HELP, HELD, HELPFUL, HELLO` | 大小写保持；按频率排序而非固定 hello 优先。 |
| `we're ` | 空 | 带撇号的上下文覆盖不足。 |
| 空输入、`Hello. `、换行 | 空 | 句子边界不乱猜下一词。 |
| `中国` | 人、共产党、企业、国际、人民、经济 | 有相关性，新闻/机构用语偏多。 |
| `中华人民` | 共和国、共和国主席、共和国证券法… | 最长匹配优先，机构法律类偏多。 |
| `今天` | 是、在、晚上、下午、上午、早上 | 常用续词较合理。 |
| `天气` | 预报、变化、情况、炎热、寒冷、状况 | 较合理。 |
| `谢谢` → `谢谢你` | 合作、你、大家、了、您 → 们、了、啊、的爱… | 可连续候选；商务短语的频率压过日常表达。 |
| `你好` | 吗、啊、的、像、了、评度、友、处 | 后部结果由“好”的短前缀回退产生，相关性差。 |
| `今天下午` | 茶、三点、好、五点、四时… | 回退只看“下午”，失去“今天”的语境；下午茶排首不理想。 |
| `早上` | 起来、好、起床、市公司、的、海、述、面 | 三个较合理候选后，单字“上”的回退导致碎片续词。 |
| `好，` | 空 | 中文标点切断续词，符合当前策略。 |

## 候选条与风险

读码确认：中文只插入续词后缀，英文替换当前 prefix 并按后文补空格；候选点击前复核 document + before + after 锚点，换输入框/光标后拒绝旧候选。密码、URL、邮箱、验证码、选中文本与词中插入点限制仍在；Rime 有组合串时优先显示 Rime 候选，提交后再走续词。首位工具栏返回按钮和 44pt 点击高度仍保留，本次未改布局。

后续优化应先处理短中文后缀回退的相关性门槛、日常对话词频、英文常用搭配及缩写覆盖。当前缺少真实输入语料评测，不能为几条示例加入硬编码排序；需用户在聊天连续输入、选词、删除、切输入框后验收。
